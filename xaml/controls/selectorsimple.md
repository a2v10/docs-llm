# SelectorSimple

> A shorthand Selector that derives its fetch command, browse dialog, and display property from a single Url by naming convention.

## Overview

`SelectorSimple` is a shortened form of the regular [Selector](https://docs-llm.a2v10.com/xaml/controls/selector.md). Instead of wiring up the fetch command, the lookup dialog, and the display property by hand, you specify a single `Url` property — everything else is generated by convention.

The endpoint pointed to by `Url` must contain a `browse` dialog and a `fetch` command; those are exactly what `SelectorSimple` calls by default. See [Dialogs](https://docs-llm.a2v10.com/model/dialogs.md) and [Commands](https://docs-llm.a2v10.com/model/commands.md) for how they are declared in `model.json`.

It inherits from `Selector → ValuedControl → Control → UIElement → UIElementBase`, so every property of the base selector remains available.

## Use When

- The lookup endpoint follows the standard layout — a `browse` dialog and a `fetch` command — and no custom search behaviour is needed.
- The displayed property is `Name`.

## Do Not Use When

- Search must run through a JavaScript delegate, or the dropdown needs a custom panel, a create-new pane, or a display property other than `Name` — use the full [Selector](https://docs-llm.a2v10.com/xaml/controls/selector.md) instead.

## Syntax

```xml
<SelectorSimple Value="{Bind Document.Agent}" Url="/catalog/agent" />
```

## Properties

| Property | Type | Description |
|----------|------|-------------|
| `Url` | String | URL of the [endpoint](https://docs-llm.a2v10.com/model/overview.md). The endpoint must contain a `browse` dialog and a `fetch` command. |
| `Data` | Object | **Bind only.** Extra parameters for the lookup. |
| `Folder` | Boolean | If `true`, calls `fetchfolder` and `browsefolder` instead of `fetch` and `browse`. Used for lookups into hierarchical catalogs. |

See [Selector](https://docs-llm.a2v10.com/xaml/controls/selector.md) for the inherited properties, and [Base Classes](https://docs-llm.a2v10.com/xaml/base-classes.md) for `Label`, `Required`, `Disabled`, and the rest.

## Defaults

From the given `Url`, `SelectorSimple` builds the remaining properties of the base `Selector` itself:

| Base selector setting | Derived value |
|-----------------------|---------------|
| Fetch command | `Url + '/fetch'` |
| Browse dialog | `Url + '/browse'`, with a search icon |
| `DisplayProperty` | `Name` |
| Dialog argument | the current `Value` |

## Example

This XAML:

```xml
<SelectorSimple Value="{Bind Document.Agent}" Url="/catalog/agent" />
```

is effectively equivalent to:

```xml
<Selector Value="{Bind Document.Agent}" DisplayProperty="Name"
          Fetch="/catalog/agent/fetch">
  <Hyperlink Icon="Search" Command="{BindCmd Browse, Url='/catalog/agent/browse'
             Argument={Bind Document.Agent}}" />
</Selector>
```

With a label, a required mark, and extra lookup parameters:

```xml
<SelectorSimple Label="Partner"
                Value="{Bind Document.Agent}"
                Url="/catalog/agent"
                Data="{Bind Document.Company}"
                Required="True" />
```

Lookup from a hierarchical catalog:

```xml
<SelectorSimple Label="Category"
                Value="{Bind Document.Category}"
                Url="/catalog/itemcategory"
                Folder="True" />
```

## Notes

- If `Data` is set, it is used as parameters both for the browse dialog and for the server fetch — in effect `Data` is simply duplicated into the base selector's `FetchData`.
- `Folder="True"` changes only the called names: `fetchfolder` and `browsefolder` must exist in the endpoint.
- Anything the shorthand does not cover can still be set explicitly, because every base `Selector` property is inherited.
